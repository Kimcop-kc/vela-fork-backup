# 文风仿写与去 AI 味（Skill 驱动）

这两个功能都由**可替换的 Skill** 提供语义方法：代码负责证据、预算与落盘，Skill 负责「怎么读、怎么写」。
用户把自己的 `SKILL.md` 放到 `~/.vela/skills/<name>/` 即可整体替换方法，无需改代码。

| 功能 | Skill 名 | 作用 |
|------|----------|------|
| 文风仿写 | `style-imitation` | 参考文本 → 有证据的可执行文风指南 |
| 去 AI 味 | `de-ai-tone` | 按标记的可修订位置做语义改写 |

## 一、文风仿写

### 1. 目标

把一段参考文本编译成**可执行**的文风指南：每条规则都能指回参考文本里的原文片段。
「文笔优美」这类无法执行、无法溯源的结论不允许进入指南。

### 2. 核心不变量：无证据不入指南

```ts
// 模型归纳的规则：缺少证据 / 类别无法识别 → 直接丢弃，并计入 skipped
parseLlmRules(rawLlmRules, referenceText, skillName)
```

量化规则与模型规则走同一条约束：`deriveMetricRules` 拿不到证据的规则同样跳过。
渲染时每条规则下面都会列出证据原文。

### 3. 量化分析（`measureStyle`）

净字数、句子数、段落数、平均句长、句长变异系数、对话占比、平均段长、
用词多样性（不同 2-gram / 全部 2-gram）、标点频次（每千字）、高频特征表达、
以及最短句/最长句/对白句三类样本句（带偏移）。

这些指标既作为 Prompt 里的客观依据，也直接推导出一部分规则。

### 4. 分段编译

参考文本过长时按 token 预算切分（`splitStyleReference`），逐段归纳后合并；
单段失败不会放弃整体 —— 量化规则依然能编译出一份有证据的指南，日志会说明失败段数。

### 5. 落盘与查看

- 是否写入项目文风设定由 `applyToProject` **显式**决定（不勾选时只生成、不改动现有设定）；
- 编译完成后打开 `style-guide` 页签查看指南全文（`renderStyleGuide` 的 markdown）。

### 6. 入口

小说配置编辑器 →「文风配置」→「从参考文本编译文风指南」：
粘贴参考文本（至少 200 字）+ 来源标题，选择是否写入项目设定，然后启动
`createCompileStyleGuideWorkflow`。

## 二、去 AI 味

### 1. 只标记 → 显式改写

AI 痕迹检测（高频词、句式单调、过度总结）只产出**可修订位置**：
位置、原文片段、量化指标、修订方向。它不改稿，也不按隐藏词表替换文本。

只有用户显式调用时（审稿报告里的「去 AI 味」按钮 / `createDeaiReviseWorkflow`），
才会把标记交给 Skill 做语义改写：

```ts
new DeaiReviseCommand({ chapterNumber, chapterTitle, draftPath, draftContent, kinds })
```

### 2. 结果形态

改写结果以**待审阅修订**（`revisionType: 'deai'`）落盘并打开 diff 页签，
由用户确认后再采用，不会自动替换原稿。

### 3. 长章节

按 token 预算分段改写：每段只处理落在本段范围内的标记，段间不重复、不遗漏。

## 三、测试

`src/services/__tests__/style-imitation.test.ts` 覆盖：

- 模型规则缺少证据 / 空证据 / 类别无法识别时被丢弃；
- 量化规则同样全部带证据；
- 渲染结果只包含带证据的规则，并标明编译用的 Skill。
